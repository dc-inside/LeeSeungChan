### 📝 기능명세서 (Functional Specification)

**프로젝트명:** 1차 프로젝트 - 영양소 섭취 기반 고콜레스테롤혈증 위험도 예측 및 자가 진단 웹 서비스

| 구분 | 기능명 | ID | 세부 동작 및 로직 |
| --- | --- | --- | --- |
| **프론트엔드** | 3단계 데이터 입력 캐러셀 UI | FR-01 | 사용자가 스크롤 피로도 없이 복합적인 건강 데이터를 입력할 수 있도록, 대시보드 좌측 영역(`predict-left-pane`)에 기본 정보, 영양소 프로필, 생활 습관으로 구성된 3단계 캐러셀(Carousel) 형태의 입력 폼을 배치 |
| **프론트엔드** | BMI 실시간 자동 연산 | FR-02 | 사용자가 신장(cm)과 체중(kg) 수치를 입력하는 즉시, 페이지 새로고침이나 서버 통신 없이 JavaScript를 통해 신체질량지수(BMI)를 실시간으로 자동 계산하여 화면에 즉각 반영 |
| **프론트엔드** | 대시보드 상태 유지 및 필터링 | NFR-05 | 예측 완료 또는 데이터 재조회 후 페이지가 리렌더링될 때, 웹 POST 데이터(String)와 백엔드 데이터형(Int)의 불일치로 라디오 버튼이나 셀렉트 박스가 초기화되는 것을 막기 위해 Jinja2의 `string` 필터를 적용하여 사용자 선택 상태를 엄격히 유지 |
| **프론트엔드** | 결과 시각화 및 대기 화면 제어 | FR-04, FR-05 | 초기 진입 시 우측 영역(`predict-right-pane`)에 '예측 대기 중' 플레이스홀더를 노출해 UI 밸런스 유지. 백엔드로부터 예측 결과를 수신하면 위험도 3단계 레이블 게이지와 특성 중요도 상위 5개(Top 5) 항목을 프로그레스 바 차트 형태로 동적 매핑하여 시각화 |
| **프론트엔드** | ID 검색 및 스크롤 제어 | FR-07, 제약사항 | 불필요한 뎁스(Depth)를 줄이기 위해 상단 GNB(Global Navigation Bar)에 Analysis ID 검색창을 상시 배치함. 결과 도출 후 대시보드가 길어질 때 발생할 수 있는 스크롤 오류를 방지하기 위해 '문서 전체 높이 - 푸터 높이 - 화면 높이'를 실시간 역산하여 안착시키는 수학적 스크롤 제어 JS 로직을 구동 |
| **백엔드** | ML 모델 및 Imputer 메모리 상주 | NFR-01 | 서버 부팅 단계(`__init__.py`)에서 `joblib`을 통해 사전 학습된 랜덤 포레스트 모델(`.pkl`)과 결측치 처리기(Imputer)를 단 한 번만 로드하여 앱 컨텍스트(`app.config`)에 상주시키는 싱글톤 패턴을 수행, 예측 요청 시마다 발생하는 디스크 I/O 오버헤드를 원천 차단 |
| **백엔드** | 관심사 분리(SoC) 기반 라우팅 | NFR-02 | Application Factory 패턴(`create_app`)과 Blueprint 가이드에 따라 구조 분할. 단순 화면 렌더링을 담당하는 `main_views.py`와 데이터 전처리, 모델 예측 및 DB 통신을 전담하는 `predict_views.py`로 라우팅 모듈을 철저히 분리하여 유지보수성을 극대화 |
| **백엔드** | 데이터 정합성 검증 및 융합 예측 | FR-04, NFR-03 | 프론트엔드 폼에서 전달된 복합 피처 데이터를 수신하여 Pandas DataFrame으로 변환. 모델 훈련 당시의 컬럼 순서 속성(`feature_names_in_`)을 동적으로 호출하여 입력 구조를 자동 매칭하고 결측치를 보정, 랜덤 포레스트 알고리즘을 통해 위험도를 3단계(Class 0: 정상, Class 1: 경계, Class 2: 위험)로 정밀 분류 |
| **백엔드** | 고유 식별자 생성 및 다중 테이블 영속화 | FR-03, FR-06 | 사용자가 'Predict Now'를 요청한 신규 데이터일 경우, 고유 세션 식별을 위해 8자리의 영문/숫자 조합 난수로 구성된 고유 ID(Analysis ID)를 자동 생성(`generate_patient_id`). 이후 입력 데이터 전반과 예측 결과를 Oracle DB 내 외래키로 정규화 연결된 4개의 테이블(`PatientMaster`, `BasicInfo`, `Nutrition`, `Activity`)에 안전하게 분산 저장 |
| **백엔드** | 발급 ID 기반 역직렬화 및 결과 복원 | FR-07 | 사용자가 상단 GNB 검색창을 통해 Analysis ID 조회를 요청(HTTP GET)하면, Oracle DB에서 해당 식별자와 매핑된 데이터를 역직렬화하여 로드. 폼 데이터 복원과 동시에 모델의 특성 중요도(`feature_importances_`) 속성을 실시간 재추출하고 결과 플래그(`result=True`)를 활성화하여 템플릿으로 전달 |
