### 📝 요구사항 분석서 (Requirements Analysis Document)

---

📌 1. 프로젝트 개요

최근 외식 및 가공식품 섭취 빈도가 증가하고 지방, 나트륨, 당류의 과잉 섭취가 일상화됨에 따라 고콜레스테롤혈증과 같은 만성질환 유병률이 꾸준히 증가. 
그러나 이상지질혈증의 국가 건강검진 주기가 4년으로 길어 일상적인 조기 대처 및 예방 관리가 어려움. 
이에 정기 검진 사이의 공백기 동안 사용자가 스스로 일상 생활 습관과 영양소 섭취 데이터를 기반으로 위험도를 예측하고 관리할 수 있도록 머신러닝 모델을 융합한 자가 진단 웹 서비스를 제공

클라이언트(웹 브라우저) - 서버(Flask) - DB(Oracle DB)로 이어지는 안정적인 웹 서비스의 3계층(3-Tier) 데이터 파이프라인을 구축
이를 위해 Application Factory 패턴과 Blueprint 기반의 관심사 분리(SoC)를 적용하였으며, 머신러닝 모델 로드 시 발생하는 디스크 I/O 병목을 제거하고자 싱글톤(Singleton) 형태의 메모리 상주 방식을 채택

---

👥 2. 사용자 유형

**자가 건강 관리자 (Self-Health Manager):** 긴 건강검진 공백기 동안 자신의 건강 상태를 상시 점검하고자 하는 일반 사용자. 
웹 인터페이스를 통해 3단계 신체·영양·습관 데이터를 입력하여 고콜레스테롤혈증 위험도를 스스로 판별하고, 도출된 정량적 위험 요인을 기반으로 일상 속 선제적인 건강 관리를 실천하고자 하는 실무 사용자

⚙️ 3. 기능 요구사항 (Functional Requirements)

| ID | 요구사항 명 | 세부 설명 |
| --- | --- | --- |
| **FR-01** | 3단계 사용자 데이터 입력 | 사용자는 웹 UI 화면에서 총 3단계(기본 정보, 영양소 프로필, 생활 습관)에 걸쳐 복합적인 건강 데이터를 직관적으로 입력 |
| **FR-02** | BMI 자동 연산 로직 | 사용자가 신장(cm)과 체중(kg)을 입력하는 즉시 시스템 내부에서 신체질량지수(BMI) 수치를 자동 계산하여 화면에 실시간으로 반영 |
| **FR-03** | 고유 식별자(Analysis ID) 생성 | 신규 데이터 입력 시, 시스템은 개별 세션 식별 및 추후 데이터 재조회를 보장하기 위해 8자리의 영문/숫자 난수로 구성된 고유 ID(Analysis ID)를 자동 생성 |
| **FR-04** | 머신러닝 기반 위험도 예측 및 분류 | 랜덤 포레스트(Random Forest) 모델을 통해 사용자의 고콜레스테롤혈증 위험도를 Class 0(정상), Class 1(경계), Class 2(위험)의 3단계로 정밀 분류하여 제공 |
| **FR-05** | 주요 위험 요인 도출 | 예측 결과 출력 시, 모델 판별에 가장 큰 영향을 미친 상위 5가지 주요 요인(Feature Importance Top 5)을 정량적인 퍼센티지 데이터로 도출 |
| **FR-06** | End-to-End 데이터 영속성 보장 | 일회성 계산기를 넘어 실제 서비스 격의 데이터 관리를 수행하기 위해, 예측 완료된 사용자의 데이터 전반은 Oracle DB의 외래키로 연결된 4개의 테이블에 정규화되어 안전하게 보존 |
| **FR-07** | 발급 ID 기반 데이터 재조회 | 상단 GNB 검색창에 기발급된 Analysis ID를 입력하고 조회 시, 서버는 DB에서 해당 데이터를 다시 로드(GET)하여 좌측 입력 폼의 이전 선택값과 우측의 예측 결과를 화면에 완벽히 복원 |

| **NFR-05** | 대시보드 UI/UX 및 상태 유지 | 사용자가 스크롤을 내리는 피로도 없이 한눈에 입력과 결과를 대조할 수 있도록 좌우 분할(Side-by-Side) 대시보드 레이아웃을 제공 |

**[내용 구성 및 입력 피처]**

**기본 정보:** 성별, 연령, 신장, 체중, 가구소득, 교육수준 등

🚫 6. 제약사항 (Constraints)

**웹 요청 데이터 타입 불일치 제약:** 브라우저 폼(HTML POST)을 통해 유저가 선택한 라디오 버튼 및 셀렉트 박스 데이터가 서버로 넘어올 때는 모두 문자열(String) 형태로 수신. 백엔드의 정수 데이터형과 매칭되지 않아 선택창이 강제로 초기화되는 UX 붕괴를 막기 위해, Jinja2 템플릿 엔진 내 조건문 비교 연산 시 반드시 `string` 명시적 타입 변환 필터를 거치도록 프런트엔드 렌더링 규칙을 제약

**보안 및 환경 설정 격리 제한:** 데이터베이스 접속 엔드포인트(Oracle DB URI) 및 핵심 가상환경 설정 자산이 일반 비즈니스 로직 소스 코드 내에 하드코딩되는 것을 엄격히 금지, 오직 `config.py`라는 단일 설정 환경 객체 파일로 격리 분리하여 관리

**단일 목적 집중을 위한 내비게이션 설계 제약:** 불필요한 Depth를 유발하여 사용자의 직관성을 저하시키는 드롭다운(Dropdown) 구조의 메뉴 체계를 의도적으로 배제. 단일 핵심 목적인 '위험도 예측'과 'ID 조회'에만 완벽히 몰입할 수 있도록 상단의 직접 클릭 버튼 배치를 레이아웃 규칙으로 한정

**네비게이션 간격 보정 및 스크롤 제어 제약:** 콘텐츠가 가려지는 현상을 방지하고자 메인 화면 텍스트 상단 및 결과창에 명확한 여백 설정(`padding-top`)을 의무화. 또한 결과 도출 후 화면이 길어질 때 스크롤 튕김이나 마우스 드래그 시 변수가 꼬이는 오작동을 차단하기 위해 '문서 전체 높이 - 푸터 높이 - 화면 높이'를 실시간 역산하여 안착시키는 수학적 스크롤 제어 JS 로직을 포함

🎯 7. AI 모델 평가 기준 (Evaluation Metrics)

**정량적 평가:** 고콜레스테롤혈증 위험도 분류를 위한 머신러닝 알고리즘으로 대량의 다각도 건강 피처(Feature) 연산에 탁월한 성능을 보이는 랜덤 포레스트(Random Forest) 분류 모델을 탑재. 다중 분류 환경 및 클래스 불균형 보정(SMOTE) 상태를 고려하여 단순 Accuracy(정확도) 외에도 각 클래스별 스코어를 균등하게 반영하는 Macro F1-score 평가지표의 유효성을 정량적 검증 기준으로 삼음. 최종 훈련 완수 후 서버의 오버헤드를 막기 위해 joblib 기반의 싱글 파일(.pkl) 형태로 빌드 및 동기화되어 정상 연동되어야 함.

**정성적 평가:** 훈련 모델 내부의 특성 중요도(`feature_importances_`) 속성을 연산 파이프라인에서 실시간으로 추출, 사용자가 입력한 데이터 중 위험도를 높이는 데 기여한 상위 5가지 주요 요인을 정량적인 퍼센티지 형태로 도출. 도출된 주요 요인은 대시보드 화면 우측 영역에 프로그레스 바(Progress Bar) 및 직관적인 시각화 차트 형태로 정확히 매핑하여 출력함으로써 사용자가 결과의 근거를 과학적으로 납득할 수 있도록 구현되었는지 최종 검증
