기존 법률 도메인에서 'IT 개발자 오류 로그 분석 및 해결책 어시스턴트'로 성공적으로 피벗하신 기획에 맞추어 기능명세서도 완벽하게 업데이트해 드립니다. 1차 프로젝트의 프롬프트 화면 연동과 로컬 WSL 환경의 특성을 모두 반영하여 마크다운 문서로 정돈했습니다.

### 📝 기능명세서 (Functional Specification)

* 
**프로젝트명:** 3차 프로젝트 - IT 개발자 오류 로그 분석 및 해결책 AI 어시스턴트 



| 구분 | 기능명 | ID | 세부 동작 및 로직 |
| --- | --- | --- | --- |
| **프론트엔드** | 에러 로그 입력 화면 | FR-01 | 기존 1차 프로젝트의 프롬프트 화면(Navi Bar) 중앙에 에러 로그나 터미널 출력 메시지를 입력할 수 있는 텍스트 영역(textarea)을 배치하며, "분석할 에러 로그를 입력하세요"라는 안내 문구를 띄워둠 |
| **프론트엔드** | 글자 수 제한 및 제어 | FR-01 | 텍스트 입력은 최대 1,000자까지로 제한하고 우측 하단에 실시간 글자 수를 표시, 초과 입력 시 키보드 입력을 차단하고 화면에 토스트 메시지 형태의 팝업 이벤트 출력 |
| **프론트엔드** | 분석 요청 및 로딩 | FR-02 | 입력창이 비어있을 때 버튼 클릭 시 경고창을 띄우고, 내용이 있으면 서버 요청 후 응답 전까지 로딩 애니메이션을 띄우며 대기 중 버튼 중복 클릭을 방지 |
| **프론트엔드** | 결과 출력 및 안내 조항 | FR-04 | 분석 결과 출력 시 하단에 "본 해결책은 AI가 분석한 참고용 가이드이며, 사용자의 로컬 환경 및 버전에 따라 실행 결과가 다를 수 있습니다. 프로덕션 환경 적용 전 반드시 코드를 테스트하십시오."라는 문구를 강제로 노출 |
| **백엔드** | 데이터 수신 | FR-02 | 1차 프로젝트 화면(프론트엔드)에서 입력된 데이터를 REST API 방식을 통해 JSON 형태로 WSL 내부에 구축된 Flask 서버에 전송받아 파싱 |
| **백엔드** | AI 추론 및 결과 반환 | FR-03 | 전달받은 에러 텍스트를 파인튜닝된 LLaMA 3.2 3B 모델에 통과시켜 원인 분석 및 해결 코드가 포함된 결과물을 생성하고, 완료되면 다시 JSON 형태로 프론트엔드에 반환 |
| **백엔드** | 예외 및 오류 처리 | NFR-02 | 모델 추론 목표 시간 초과 시 프론트엔드에 408 에러 코드를 반환, 로컬 서버 내부(VRAM 부족 등)에 문제가 생기면 500 에러 코드를 반환하고 시스템 장애 메시지 노출 |
