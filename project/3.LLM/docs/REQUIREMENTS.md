# 📝 요구사항 분석서 (Requirements Analysis Document)

## 📌 1. 프로젝트 개요

개발 중 발생하는 복잡한 에러 로그나 터미널 출력 메시지를 **LLaMA 3.2 3B** 모델을 활용하여 분석하고, 에러의 원인과 해결 코드 및 가이드를 제시하는 전문가용 AI 챗봇 서비스 구축.

비용 최적화를 위해 로컬 WSL 환경의 Flask 서버에서 구동되며, **REST API 기반**으로 LLM 추론 결과를 반환함.

---

## 👥 2. 사용자 유형

* **IT 개발자 및 학습자:** 코딩 중 발생하는 원인 모를 에러를 빠르게 분석하고 정확한 해결 코드를 얻어 개발 시간을 단축하고자 하는 사용자.
* **시스템 관리자:** 텐서보드(TensorBoard)를 활용해 모델 학습 중 `eval/loss` 지표를 실시간으로 모니터링하고 파인튜닝 환경을 관리하는 역할.

---

## 📊 5. 데이터 요구사항 (Data Requirements)

* **포맷:** 지시사항을 정확히 따르도록 `Instruction`, `Input`, `Output` 형태의 **Alpaca 데이터셋 구조**를 준수함.
* **내용 구성:** * `Instruction`: "다음 에러 로그를 분석해줘" 등의 고정 지시어 기입
* `Input`: 수집한 실제 에러 코드나 터미널 출력 메시지 배치
* `Output`: 에러 원인 설명 및 실제 작동 가능한 해결 코드 매핑


* **데이터 출처:** 캐글(Kaggle)에 구축된 고품질 개발자 Q&A 쌍인 **'Stack Overflow Python QA'** 데이터셋 활용.

---

## 🚫 6. 제약사항 (Constraints)

* **리소스 한계:** 비용 절감을 위해 Cloud Ubuntu 대신 **로컬 데스크톱의 WSL 환경**에서 학습 및 Flask 서버를 구동함. 로컬 GPU의 VRAM 제약을 극복하기 위해 4-bit 양자화(Quantization)를 적용하고, PEFT(**LoRA**) 기법을 통한 부분 가중치 학습만을 수행함.
* **라이선스 한계:** LLaMA 3.2 모델을 활용한 파생 모델 배포 시 반드시 **"Built with Meta Llama 3"** 또는 **"Llama 3.2"** 출처를 명시해야 함. 또한, 모델이 생성한 답변을 활용해 Meta의 LLaMA와 경쟁할 만한 타 대규모 언어 모델을 학습시키는 행위는 금지됨.

---

## 🎯 7. AI 모델 평가 기준 (Evaluation Metrics)

* **정량적 평가:** 훈련 과정에서 텐서보드(TensorBoard)를 활용하여 훈련 손실(Training Loss)과 검증 손실(Validation Loss)이 안정적으로 동반 하락하는 우하향 그래프를 그리는지 실시간 모니터링하여 과적합(Overfitting)을 방어함.
* **정성적 평가:** 샘플 에러 코드 및 개발 질문 테스트를 진행하여, 생성된 해결 코드가 문법적 오류 없이 실제 사용자의 로컬 환경에서 작동 가능한지 교차 검증함.
