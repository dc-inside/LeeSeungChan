# 📝 요구사항 분석서 (Requirements Analysis Document)

## 📌 1. 프로젝트 개요
일반인이 이해하기 어려운 법률 용어, 판결문, 계약서 등을 LLaMa 3.2 3B 모델을 활용해 일상적인 언어로 쉽게 풀이하고 요약하는 AI 챗봇 서비스 구축

REST API 기반으로 Flask 서버에서 LLM 추론 결과 반환

---

## 👥 2. 사용자 유형
**일반 사용자:** 법률 지식이 부족하여 계약서나 판례 해석에 어려움을 겪는 개인

**시스템 관리자:** LLM 모델의 성능을 모니터링하고 파인튜닝 데이터를 업데이트하는 역할 수행

---

## ⚙️ 3. 기능 요구사항 (Functional Requirements)

| ID | 요구사항 명 | 세부 설명 |
| :--- | :--- | :--- |
| **FR-01** | 텍스트 입력 | 사용자는 1차 프로젝트 UI를 통해 최대 1,000자 이내의 법률 원문(판례, 조항 등)을 입력 |
| **FR-02** | 데이터 전송 | 입력된 데이터는 REST API를 통해 JSON 형태로 Flask 백엔드 서버로 전송 |
| **FR-03** | AI 요약 및 풀이 | 전송된 텍스트는 로드된 파인튜닝 LLaMa 3.2 3B 모델의 추론(Inference)을 거쳐 일상어로 요약된 결과물로 반환 |
| **FR-04** | 자동 면책 조항 삽입 | 챗봇의 응답 결과 하단에는 면책 조항(Disclaimer) 문구가 하드코딩되어 강제 출력 |

---

## ⚠️ 4. 비기능 요구사항 (Non-Functional Requirements)

| ID | 요구사항 명 | 세부 설명 |
| :--- | :--- | :--- |
| **NFR-01** | 신뢰성(Reliability) 확보 | 법률적 사실과 다른 내용을 지어내는 환각(Hallucination) 현상을 최소화 |
| **NFR-02** | 응답 속도 | 사용자가 텍스트를 입력한 후, 모델 추론을 거쳐 결과를 화면에 띄우기까지 목표 시간(60초) 이내에 완료 |
| **NFR-03** | 위험 관리(Risk Management) | AI의 답변이 실제 법적 조언으로 오인되는 것을 막기 위한 안전장치 마련 |

---

## 📊 5. 데이터 요구사항 (Data Requirements)
**포맷:** 학습 데이터는 Alpaca 데이터셋 구조(`Instruction`, `Input`, `Output`)를 준수

**내용 구성:** `Input` 영역에는 실제 법률 조항이나 판례 원문을 배치하고, `Output` 영역에는 이를 쉽게 풀어쓴 요약본을 넣어 파인튜닝 진행

**데이터 출처:** 국가법령정보센터-공공 데이터(제공: 법제처), 대법원 종합법률정보-실제 판결문과 법적 다툼의 맥락 학습

---

## 🚫 6. 제약사항 (Constraints)
**리소스 한계:** 비용 절감을 위해 모델 학습은 데스크톱 환경에서 진행, AI 모델 추론을 위한 Flask 서버는 노트북의 WSL 환경에서 구동. 로컬 하드웨어의 VRAM 제약을 고려하여 4-bit 또는 8-bit 양자화를 적용하고, LoRA 기법을 통한 부분 가중치 학습만을 수행

**법적 한계:** AI의 답변은 특정 개인의 상황에 대한 맞춤형 법률 상담을 제공해서는 안 되며, 변호사법 위반을 방지하기 위해 일반적인 '문서 해석 및 요약'에만 국한

---

## 🎯 7. AI 모델 평가 기준 (Evaluation Metrics)
**정량적 평가:** 훈련 과정에서 텐서보드를 활용하여 훈련 손실과 검증 손실이 안정적으로 하락하는지 모니터링

**정성적 평가:** 샘플 법률 문서를 50개 선정하여 테스트를 진행, 생성된 요약본에 논리적 오류가 있거나 사용자에게 치명적인 독소조항을 누락하지 않았는지 사람이 직접 교차 검증
