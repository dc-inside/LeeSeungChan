### 📝 기능명세서 (Functional Specification)

**프로젝트명:** 2차 프로젝트 - YOLOv8 기반 공사장 안전장비 객체 탐지 및 웹 모니터링 시스템

| 구분 | 기능명 | ID | 세부 동작 및 로직 |
| --- | --- | --- | --- |
| **프론트엔드** | 동영상 파일 업로드 화면 | FR-01 | 윈도우 Flask 웹 UI 화면에 사용자가 5~10초 분량의 공사장 작업 영상 파일(.mp4)을 선택하여 입력할 수 있는 업로드 폼(Form) 구역을 배치 |
| **프론트엔드** | 파일 입력 잠금 및 제어 | FR-01 | 사용자가 '분석하기' 버튼을 누르는 즉시 추가적인 파일 변경이나 중복 파일 탐색기 오픈을 전면 차단하기 위해 입력창을 비활성화(`disabled`) 처리하고, 마우스 포인터 접근을 막는 `.disabled` CSS 클래스를 동적 적용 |
| **프론트엔드** | 비동기 분석 요청 및 로딩 | FR-02 | 화면 새로고침 없이 매끄러운 사용자 경험을 제공하기 위해 기존 Form 전송 대신 JavaScript의 `fetch API`를 호출하여 비동기 통신을 수행하며, 웹 브라우저 화면에 로딩 애니메이션(Spinner)을 노출하고 버튼 중복 클릭을 원천 방지함. |
| **프론트엔드** | 결과 화면 전환 및 안내 조항 | FR-04 | 비디오 처리가 완료되면 로딩 스피너가 멈추고 분석 결과 영상의 첫 프레임을 정지 화면 대기 상태로 노출하며, 하단에 현장 환경에 따른 오탐지 가능성을 명시한 면책/안내 경고 문구를 고정 노출 |
| **프론트엔드** | 결과물 파일 다운로드 | FR-04 | 분석이 성공적으로 마무리된 시점에 성공 창 내부에서 '결과 영상 다운로드' 버튼을 활성화, 사용자가 전달받은 안전장비 바운딩 박스 합성 영상(.mp4)을 로컬 PC에 즉시 다운로드할 수 있도록 지원 |
| **백엔드**(윈도우) | 데이터 수신 및 무상태 릴레이 | FR-02 | 프론트엔드 화면에서 유입된 대용량 바이너리 비디오 데이터를 RESTful API 설계 원칙에 따라 HTTP 본문에 담아 **HTTP POST (form-data)** 방식으로 수신하며, 이를 WSL2 내부 AI 서버(포트 5001, 엔드포인트 `/predict-video`)로 세션 기억 없이 독립적으로 토스 |
| **백엔드**(WSL2) | 비디오 파싱 및 AI 객체 추론 | FR-03 | 윈도우 관문 서버로부터 릴레이된 비디오 파일을 `OpenCV` 모듈을 가동해 프레임 단위로 파싱. 이후 지정된 경로의 YOLOv8 Nano 최적 가중치 모델(`best.pt`)을 호출하여 3대 핵심 클래스(`0: Head`, `1: Helmet`, `2: Vest`)를 실시간 추론 |
| **백엔드**(WSL2) | 영상 인코딩 및 결과 반환 | FR-03, FR-04 | AI 추론을 거쳐 각 객체 위에 시각적 바운딩 박스 처리가 완료된 프레임들을 다시 동영상 파일로 최종 재합성. 리눅스-윈도우 환경 간 코덱 불일치 오류를 방지하는 `avi_path` 예외 처리 트리거를 작동시킨 후, HTTP 헤더 표준 포맷 규격(`mimetype='video/mp4'`)을 명시하여 윈도우 서버로 반환 |
| **백엔드**(윈도우) | 최종 파일 송출 | FR-04 | WSL2 AI 백엔드 서버로부터 가공 완료된 영상을 성공적으로 리턴받는 즉시, 사용자의 브라우저 화면 및 다운로드 스트림으로 최종 결과물 비디오를 완전 전송 |
| **백엔드** | 타임아웃 및 호환성 예외 처리 | NFR-02 | 동기식 REST API 통신 환경에서 긴 대기 시간으로 인한 브라우저 HTTP 타임아웃 에러(Gateway Timeout)가 터지는 것을 막기 위해 비디오 업로드 길이를 5~10초 단건 클립으로 제한하는 유효성 검증 예외 처리를 수행 |
